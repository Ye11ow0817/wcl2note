# WCL2NOTE

将 Warcraft Logs 战斗记录转换为 MRT／NSRT 团队笔记的 **Windows Electron 应用**。
UI 来自 `F:\CodexProjects\wcl2note-web` 当前版本，功能以 `F:\CodexProjects\wcl2mrt` 原 Windows app 为准。
两个参考项目保持原样；本项目可以独立开发、构建和运行。

## 直接使用

运行 `npm run package:win` 或双击 `package-win.cmd` 后，生成安装包，输出到 `release/`：

- `WCL2NOTE-版本号-win-x64-setup.exe`：当前用户安装版，可选择安装目录，提供桌面／开始菜单快捷方式与卸载入口。
- `update.json`、`SHA256SUMS.txt`：工作流发布使用的更新清单及校验值。文件名只含版本号，不含日期。

`npm run package:win:dir` 可单独生成 `release/win-unpacked/` 目录版，运行时需保留整个文件夹。

正式应用启动后在后台检查 GitHub Releases，发现更高版本时在设置按钮旁显示蓝色「更新」。点击后直接下载安装包，按钮显示青色下载百分比；校验时显示紫色「校验中…」，失败显示红色「重试」，校验通过后显示绿色「安装」。点击安装会运行安装程序并退出当前应用。设置的更新区域仅保留「检查更新」和同款操作按钮，两处状态同步。没有可用更新时隐藏操作按钮，手动检查结果以简短文本显示。已有本机配置继续保留；开发模式不自动检查。

默认分支推送和手动运行 Actions 会生成安装包供下载；推送与 `package.json` 版本一致的 `vX.Y.Z` 标签会自动发布 GitHub Release。发布步骤、更新源和验收方式见 [发布与应用更新](docs/releases.md)。

粘贴报告链接或编号 → 加载报告 → 选择战斗和 Pull／阶段 → 选择角色、队友／敌对和 Buff／Debuff／施法 → 勾选技能 → 在 Note 预览中选择 MRT／NSRT → 复制笔记或另存为 TXT。
顶部工具栏集中显示报告输入、加载、更新和设置；更新按钮仅在发现新版本后显示。首页底栏及其提示和撤销入口已移除；设置内显示「WCL2NOTE / 版本号 / Ye11ow」。下方独立一行选择战斗与阶段；分析区位于左侧，Note 位于右侧并默认展开，可随时收起。在 960×720 最小窗口下，各列表独立滚动，展开 Note 时复制与保存按钮保持可见。
界面统一使用深灰蓝背景、浅色文字和青绿色强调色；角色菜单、设置与笔记预览沿用同一套颜色层级，较暗的职业色适当提亮以保持文字可读。
技能名称左侧显示技能图标；actor 排行、选择菜单、当前选中项和时间轴角色分组仅为玩家显示当前战斗的专精图标，来自 WCL `playerDetails`；专精缺失或图片下载失败时回退职业图标。NPC、Boss、宠物和实例不显示 actor 图片或占位。图片按可见项加载：先读取 `%APPDATA%\WCL2NOTE\icon-cache\v1`，缺失时由主进程从 `assets.rpglogs.com` 下载并缓存。仅内置魔兽红色问号，作为技能／职业图标失败时的默认图标；其余图标仍按需下载。默认图标和已缓存图片可离线显示，WCL 报告查询仍需要联网。
战斗列表在原界面内展开，展开时隐藏整个分析区和 Note；按首领及难度分组，组内分别显示 Kill 与 Wipe。多场战斗的首领仅通过最右侧整行高度、带边框的按钮展开／收起；点击名称或战斗信息直接选择该首领最近一次击杀，没有击杀时选择最近一次战斗。只有一场战斗的首领不显示展开按钮，点击整行直接选择该场战斗。条目显示结果编号、持续时间和本地开始时间，灭团有原始血量、结束阶段和整体进度时一并显示。阶段下拉与选择框等宽，展开阶段会收起战斗列表，两者不会同时展开。设置以弹窗打开，支持 Esc 关闭并将焦点返回设置按钮；版本号也在设置中查看。
团本和大秘境分组优先显示，Boss 名称后为左对齐的结果、时长和开始时间，名称保留独立空间，长名称可以换行。Trash Fights 位于底部独立区域，采用 WCL 的浅蓝色紧凑文本行，逐场显示「名称 (时长) 开始时间」，按时间排序并直接点击选择；同名小怪的多场战斗也分别列出。链接指定 `fight`（包括 `fight=last`）时，加载后战斗列表默认收起，初次手动展开时展示对应战斗的 Boss 分组，单场 Boss 或 Trash Fight 仅标记选中；未指定 `fight` 的链接或报告编号默认展开战斗列表，所有 Boss 分组初始收起。重新加载报告会重新应用这些初始状态。
通过 Windows 标题栏缩放、最大化或关闭窗口；Alt 显示菜单，Ctrl+C/V 等使用标准编辑快捷键，支持右键复制、粘贴与全选。

## 技能配置

分析区第一行按「配置选择 → 保存 → 另存为 → 配置管理 → 清除勾选」排列，两种视图共用；Buff／Debuff／施法标签的位置保持不变。配置下拉只显示名称，可搜索。修改勾选时显示未保存标记，点击「保存」更新当前配置；「无」状态下有勾选时，点击「保存」会打开命名窗口创建新配置。没有修改时「保存」置灰。「另存为」只创建新配置，重名时提示换名并禁用提交，不覆盖已有配置。

配置保存在本机，数量不设固定上限，重启后记住上次使用的配置。加载新日志或新战斗时按技能 ID、事件类型和阵营匹配所有对应角色，不绑定 Actor；本场未出现的技能仍保留在配置里。切回已经编辑过的战斗时，优先恢复该场草稿。

切换配置会完全替换当前战斗的勾选，不叠加旧配置。当前有未保存修改时才询问保存、放弃或取消，普通切换直接完成；保存并切换会先保存当前配置，尚未选择配置时则先命名新建，再应用目标配置。配置只保存整项技能，存在本场单次调整时会明确提示其不写入配置。下拉顶部固定提供「无」，表示未选择已保存配置，不能覆盖、重命名或删除；可在此状态下勾选后另存为。「清除勾选」会清除当前战斗所有阶段和标签页的选择并切到「无」，保留原配置，不提供撤销。

「配置管理」可展开完整技能清单，展开项使用较亮背景、完整边框和左侧强调线，与其他收起项区分。名称旁的铅笔支持原地重命名（回车或移开焦点保存，Esc 取消），应用和复制按钮始终显示；当前配置的应用按钮显示「使用中」并禁用，不再单独显示状态标签。管理修改立即保存，底部不再提供另存为或完成按钮，通过右上角 × 或 Esc 关闭。删除配置需在确认弹窗中确认，不再提供删除撤销。技能清单只标记已加载类型中本场未出现的技能，不逐项显示已匹配；单项删除会立即保存，删除当前使用配置中的技能时，同步取消当前战斗中所有角色对应技能的勾选。配置保存整项技能规则，逐次事件的选择留在本场草稿中。

展开配置后，技能清单右上角提供「添加技能」：在同一个管理窗口内切换到技能选择，添加、取消或 Esc 后返回原配置，保留搜索、展开项和滚动位置。打开时不再加载本场所有类型的事件；输入名称／ID 停顿 300 毫秒后，先复用已有配置和完整缓存，对缺少的类型只查询名称／ID 命中的技能。类型和阵营筛选也参与搜索，改词、清空或关闭时取消旧请求，输入法组词期间不请求。搜索使用独立缓存，不会将筛选结果混入完整战斗缓存。支持跨搜索词多选，清空输入后可查看已勾选项；已添加项置前并禁选，其后为可添加项；每组按施法 → Buff → Debuff 排序，同一类型内友方在前、敌对在后，最后按名称和 ID 排序。配置清单和添加列表都在技能名称后显示 ID。候选不受主界面的阶段、角色或目标／来源筛选限制，未加载日志时也可搜索已有配置中的技能。添加后立即保存，编辑当前配置时同步勾选新增技能，并保留其他临时调整；编辑其他配置不会改变当前战斗的勾选。按技能 ID 过滤使用 [WCL API 的 filterExpression 参数](https://www.warcraftlogs.com/v2-api-docs/warcraft/report.doc.html)，只发送经校验的技能 ID。

## Note 格式

Note 预览标题栏提供 MRT／NSRT 切换，默认使用 MRT。两种格式共用友方来源、敌方来源和友方简化选项，默认依次为开启、关闭、开启，切换格式时保留选择。选项统一按两行两列排列：第一行是友方来源／敌方来源，第二行是友方简化／格式专属选项（MRT 为技能图标，NSRT 为动态计时器）。切换格式时共同选项和预览框保持对齐。

NSRT 使用首领的 EncounterID、英文难度和名称作为头部，每次事件单独一行，字段依次为 `ph;time;tag;spellid;`，不额外生成 `text`。来源开启时写入对应来源的 `tag`，关闭时直接省略整个 `tag` 字段。友方简化开启时使用职业标签（如 `MAGE`、`PALADIN`），关闭时使用来源名字；缺少职业信息或不是已知职业时也使用来源名字。宠物使用自己的来源名字。MRT 的职业简称继续使用原有规则。

NSRT 的「动态计时器」默认勾选，鼠标悬停立即提示「使用与战斗事件时间点关联的动态计时器」。勾选时 `time` 为阶段内秒数，`ph` 按阶段切换先后从 1 编号，重复进入的阶段单独计时；取消后 `time` 从开战累计，统一使用 `ph:1`。两种计时方式都取施法开始时间、精确到 0.1 秒，阶段或 Pull 筛选不会改变计时基准。复制与 TXT 保存均使用当前预览内容。

导出字段已参照 [NSRT 官方解析器](https://github.com/Reloe/NorthernSkyRaidTools/blob/main/NorthernSkyRaidTools/Reminders.lua)核对。当前计时选项仅按 WCL 阶段时间换算，尚未建立 WCL 阶段与 NSRT 各首领事件的映射；NSRT 切换阶段还会取消旧计时器，因此关闭动态后统一使用 `ph:1` 不能保证后续阶段的提醒继续触发。当前实现尚不构成完整的跨阶段计时方案。

## 可视化时间轴

报告工具栏下方提供两种视图共用的筛选区：actor 和带文字的「图表／时间轴」切换位于第一行，全部／队友／敌对独立放在 actor 下方，后面依次是 Buff／Debuff／施法和 Target（施法）或 Source（光环）。事件类型行右侧提供「全部事件／已加入 Note」显示切换。未选中的阵营使用浅灰文字，选中项保持明亮。导入报告默认显示所有队友的施法与全部事件。战斗与阶段共用顶部选择行，时间轴内不再重复提供阶段导航。Note 在图表和时间轴之间保留同一份展开／收起状态；配置和「清除勾选」统一位于两个视图的顶部，笔记的复制与保存仍位于 Note 面板。

- 阵营严格筛选图表和时间轴，不再额外保留敌对施法参照或其他阵营的已选技能。选择「全部」时，上方显示敌对、下方显示队友，阵营分类和角色分组可独立折叠；单选队友或敌对时，直接显示角色和技能，不显示阵营分类标题和折叠按钮，并忽略「全部」中的折叠状态。Buff／Debuff 与施法使用相同规则，跨标签导出勾选继续保留。
- 非瞬发施法使用 WCL 的开始与完成事件配对，绘制与技能图标等高、按法术学派着色的不透明读条；图标为 20px 方形，技能行高 27px，与 WCL 官方样式的比例一致。读条色块为完整 20px 高，图标左端和读条起点都对齐施法开始时间。蓄力使用 empowerstart／empowerend，技能名称采用 WCL 文字色，读条与图表采用 WCL 学派背景色及复合学派渐变，例如元素冲击为冰霜蓝 → 自然绿 → 火焰红；图表横条保持 WCL 的 90% 不透明度。瞬发或缺少匹配起止的事件只显示图标；开始事件不重复计数，MRT／NSRT 使用施法开始时刻并保留一位小数。
- Buff／Debuff 显示实际持续区间，视窗前已经存在的光环仍可查看；日志中仅有持续状态的光环不生成虚假的获得事件。读条按视窗裁剪显示，图标始终位于真实开始时间，可在视窗边缘显示不全或完全移出，不为显示完整而补位。
- 主时间轴默认显示前 20 秒，短战斗显示全程。上方使用视频裁剪风格的范围条，以青绿色边框标出可见范围，两端竖向拖柄调整起止时间，中间选区可整体拖动平移，点击轨道调整最近的端点。刻度和右侧固定显示的可见区间使用分秒，不显示 Phase 色带。范围条保留 Ant Design 的双端滑块交互并关闭浮动提示，避免拖动时触发弹层循环更新；两个手柄分别支持方向键、Home 和 End，并保留无障碍时间文本；阶段筛选和画布缩放会同步更新范围条。工具栏保留放大、缩小、恢复默认视窗和「已隐藏」恢复入口。
- 在时间刻度尺上拖选一段时间即可框选放大（至少 2 秒），选择框覆盖整个时间轴的可见高度，按 Esc 取消；拖动技能行空白或行下方的画布留白直接平移，无需切换鼠标模式。在时间轴上按住 Shift 滚动鼠标滚轮可左右平移，松开 Shift 后保留普通纵向滚动。聚焦画布后支持 `+`、`-`、左右箭头和 `Home`；点击「恢复默认视窗」或按 `Home`，在全部阶段下返回默认 20 秒视窗，筛选具体阶段或 Pull 时返回其完整范围。标尺最小大格为 1 秒，中间 0.5 秒处显示中刻度，其余每 0.1 秒显示短刻度；缩放时尽早切换到秒级大格，文字标签按宽度稀疏显示。悬停时以竖线提示精确时间。
- 阶段选择在图表和时间轴中含义一致：筛选当前阶段／Pull 的数据，同时筛选 Note、复制和保存内容。切换筛选保留原有勾选，回到「全部阶段」后恢复显示；「清除勾选」会清除当前战斗所有类型和阶段的勾选。时间轴缩放限制在所选阶段范围内；只移动或缩放视窗不会改变 Note。重复阶段单独编号，长名称在等宽下拉列表中换行显示。阶段沿用开战计时，Pull 的 MRT 和时间轴从 Pull 开始计时，NSRT 保留原有动态／累计时间基准。
- 未加入 Note 的事件显示无外围边框的彩色图标；已加入的事件显示强调边框和小勾，当前查看通过技能行高亮区分，键盘聚焦仍有可见提示。同一技能始终保持单行，自然重叠，不聚合、不纵向展开；可通过行内明细独立勾选同毫秒事件。
- 「全部事件／已加入 Note」位于共用事件类型行右侧，在图表与时间轴之间保持一致并按战斗记忆。「全部事件」显示当前筛选范围内的事件，「已加入 Note」仅显示其中实际勾选的事件，包含逐次选择与排除；图表沿用原有角色排行、技能条形图和 CPM／覆盖率布局，并按该显示范围统计。切换显示范围不改变 Note 勾选、复制或保存内容。通过行首复选框或事件明细选择导出，不提供区间批量加入按钮或状态图例。
- 图标、读条和光环区间在鼠标移入时立即显示两行提示：居中的技能名称，以及 `开始时间 – 结束时间`。点击图标后，底部统一明细表按「复选框、起止时间、来源、目标」显示每次事件，起止列表头按类型分别为「获得时间 – 移除时间」（Buff）、「施加时间 – 移除时间」（Debuff）和「开始时间 – 完成时间」（施法），各列居中并保留间隔；角色分组名去掉阵营前缀，并与明细中的角色名共用职业颜色。点击明细整行只选中事件，复选框单独控制该次导出，实例名称使用「名字 编号」，行首复选框选择该行；技能列表中的整组勾选可以恢复整组默认选择。逐次选择跨阶段保留；本次运行内切换战斗或图表／时间轴视图会恢复各战斗的选择、筛选、视窗、隐藏、折叠及滚动位置；更换阶段后视窗先显示该阶段范围，重新加载报告时清空战斗选择状态。
- 技能行仅显示技能图标和名称，施法者信息在角色分组和事件详情中查看。技能置顶功能已移除；「全部」阵营中的分类和角色折叠分别保留，光环页与施法页各自保留阵营折叠状态。
- 点击时间轴空白区域或将键盘焦点移到画布会收起逐次勾选明细，不改变 Note 选择。隐藏和折叠只影响时间轴，不改变导出选择或图表；「已隐藏」恢复技能行。「全部事件」中的原始日志、次数和覆盖率不受逐次排除影响，「已加入 Note」则只统计已选事件。
- 切换战斗时，如果当前选中的 actor 仍在新战斗的参与者目录或事件中，则保持选中；缺席时回到「所有」，按报告内身份校验，不按同名角色猜测。
- 「定位 Note」展开预览并选中对应输出行。施法使用开始时间，按 0.1 秒四舍五入；MRT 合并同一时间的事件，NSRT 每次事件单独一行。复制与 TXT 导出使用同一份结果。

已对比现成控件的缩放、单行重叠、自定义图标及秒级刻度能力，详见[时间轴 UI 控件调研](docs/timeline-ui-components.md)。

## WCL 凭据

无需网页登录，无需后端、EdgeOne、会话 Cookie 或 `.env` 配置。

- 默认使用与原 app 相同的本地内置 Client ID／Client Secret，不在设置界面显示默认值。
- 在设置里填写自己的 Client ID／Client Secret，输入变化后自动保存；下次启动继续使用。
- 两项都清空或点击“恢复默认”使用内置凭据；只填一项会提示不完整，不会回退或混用内置凭据。
- 自定义凭据保存于 `%APPDATA%\WCL2NOTE\credentials.json`，Secret 通过 Electron `safeStorage` 使用 Windows DPAPI 加密。默认不读取或修改原 WPF app 的设置。
- Token 仅保存在主进程内存中，过期前刷新；并发请求共享一次刷新。API 返回 401 时刷新一次后重试。
- 与原 app 一致：Token 地址为 `https://www.warcraftlogs.com/oauth/token`，GraphQL 为 `https://cn.warcraftlogs.com/api/v2/client`。输入其他地区的报告链接也仍使用 CN API。
- Client Credentials 可读取公开或不公开列出的报告；登录后私有报告不属于此认证模式的权限。

内置 Secret 位于打包后的主进程代码中，桌面程序的内置凭据仍可以被逆向提取，与原 app 有相同的分发限制。自定义 Secret 不写入渲染器存储、日志或明文配置；其输入框按密码显示。

## 保留的原 app 行为

- 报告编号、URL query／hash 中的 `fight`／`last`／`pull`／`phase` 初始选择；未指定 fight 时等待手动选择。
- 团本补充 WCL 风格的 Kill／Wipe 编号，同一报告按首领和难度分别累计击杀与灭团次数；大秘境显示层数并优先使用钥匙计时，普通战斗保持中性。开始时间按本机时区显示为 `hh:mm 凌晨／上午／下午／晚上`。
- 选择战斗后立即加载队友和敌对的施法，默认浏览队友施法；Buff、Debuff 按阵营与类型分别按需加载并缓存，已勾选的其他组合继续参与导出。每个所需组合完整读取所有分页，支持取消、超时、限流提示和重试，旧报告的迟到请求不会覆盖新报告。
- Cast、Buff、Debuff；来源树中的玩家、宠物与 Instance；所有队友视图隐藏宠物，宠物仍可单独选择。
- actor 列表参照 WCL：每列最多 10 个名字，列宽随内容自适应；移除搜索框和“选择 actor”提示。鼠标悬停角色时在右侧显示宠物，继续悬停可显示实例；靠近窗口边缘时调整浮层位置，避免裁切。玩家按职业英文名与角色名排序并使用职业色，敌对首领优先；NPC 显示游戏 ID，真实实例编号可单独筛选。同名不同 actor 保留独立条目，切换事件类型时保留目录与选择。
- 施法在“所有队友／所有敌对”下按施法次数降序显示 actor，点击行后同步选中上方 actor，再显示其技能。次数与 CPM 按当前 Pull／阶段计算，排除 WCL 的 fake 补充事件，蓄力法术在施法完成时计数。
- 事件标签下提供 Target（施法）或 Source（Buff／Debuff）下拉列表，使用相同的角色、宠物与实例菜单，可选择双方角色。三个下拉框均按当前名称自适应宽度，长名字在面板内省略显示；选中具体角色后，点击右侧叉返回对应的“所有”。Target／Source 左侧不显示文本标签，菜单项不显示叉。筛选同时作用于技能、次数、统计与 Note 预览；各阵营和事件类型分别保留筛选，本次运行内切换战斗时恢复各自筛选，重新加载报告时清空。
- 技能表移除来源列，施法显示次数和 CPM，Buff／Debuff 显示获得次数和覆盖率，相同技能合并为一行。覆盖率使用效果存在区间的并集，按当前区间裁切；刷新、叠层不重复计为获得，跨阶段持续但本阶段未获得的效果显示零次，可查看覆盖率，不生成虚假的笔记事件。
- 同一 Source 的 Instance 同步勾选，不同 Source 分开；跨事件标签和区间保留选择，切换战斗后恢复各自选择，重新加载报告时清空。
- Pull 从零计时；团本阶段仍使用整场战斗时间。MRT 时间精确到小数点后 1 位；敌方技能计数、职业缩写等输出逻辑继续保留。
- MRT 输出的技能图标默认关闭；MRT／NSRT 的友方来源默认开启、敌方来源默认关闭、友方简化默认开启。列表中的技能与职业图标始终显示。
- 技能列表、时间轴和技能配置窗口通过 Wowhead 官方标准脚本提供正式服简体中文提示，使用官方外观及加载中、成功和失败状态。现有技能图标、名称和颜色保留，等待超时与缓存由官方脚本管理；时间轴读条和事件明细继续显示起止时间。
- 原生 Windows 另存为对话框、UTF-8 TXT、Windows 换行及原生剪贴板。

## 开发与构建

需要 Node.js 22.12 或更新版本，使用 npm 和已提交的 `package-lock.json`。安装依赖时会自动下载对应版本的 Electron 运行时。

```powershell
npm ci
npm run dev
```

也可以双击 `start-dev.cmd`。开发模式自动启动 Electron 和仅供 UI 热更新的 Vite 开发服务器；修改主进程／preload 后重新启动命令。

```powershell
npm run build
npm start
npm run package:win
```

`npm start` 运行已构建的本地资源；`npm run package:win` 生成安装程序，双击 `package-win.cmd` 也可完成打包。
`npm run package:win:dir` 仅生成目录版。打包不会自动上传或发布；安装包目前不包含代码签名证书。

`package-win.cmd` 会检查并复用已满足要求的依赖，再执行 `npm run package:win`。Buff 分类索引由随源码提供的网页观察记录生成，构建时验证来源、分类值、技能 ID 和分类冲突；排名采样覆盖率可另行检查，见 [分类数据说明](data/wcl-buff-categories/README.md)。

打包会使用临时应用目录，并在确认本次 EXE 产物已生成后返回成功。

如果 GitHub 下载较慢，可以在同一 PowerShell 窗口中设置下载镜像后再安装、构建；工具仍会验证预期校验值：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_CUSTOM_DIR = '{{ version }}'
$env:ELECTRON_BUILDER_BINARIES_MIRROR = 'https://npmmirror.com/mirrors/electron-builder-binaries/'
```

```powershell
npm run typecheck
npm run lint
npm run test:unit
npm run test:electron
```

`npm test` 等同于 `npm run test:unit`。`test:electron` 会先构建，再直接启动真实 Electron，使用主进程内的测试替身模拟 WCL 响应，不需要后端或 WCL 凭据；Windows 加密、重启、剪贴板、保存文件、窗口隔离均通过真实桌面进程检查。
PowerShell 中可用 `npm.cmd run test:electron -- --grep=图标下载失败` 筛选单项测试，显式通过 Windows npm 命令入口传递参数。
测试保存对话框使用替身选择测试输出目录，不会弹出对话框要求人工操作。正式程序保留原生对话框。
Electron 集成测试需在正常 Windows 用户上下文运行。测试入口会提前拦截 `CodexSandboxUsers` 受限账户，避免触发 Electron 启动访问检查的 `0x80000003` 弹窗；Codex 执行时应使用沙箱外运行权限，原因与复验结果见 [验证记录](docs/validation.md)。

`npm run check:wcl` 可单独检查内置凭据的真实 WCL 认证，不输出凭据或 Token；`npm run check:wcl -- 报告编号` 还可检查指定报告的读取。

可用同一套测试检查目录版：

```powershell
$env:WCL2NOTE_EXECUTABLE = (Resolve-Path .\release\win-unpacked\WCL2NOTE.exe).Path
npx playwright test
Remove-Item Env:WCL2NOTE_EXECUTABLE
```

检查便携版的真实自解压启动、UI 和本地设置：

```powershell
npm run test:packaged
```

测试其他已安装或目录版文件时使用 `npm run test:packaged -- "WCL2NOTE.exe 完整路径"`；检查结果写入 `test-results/packaged/`。默认检查 `release/win-unpacked/WCL2NOTE.exe`，不会重新打包，也不会运行 NSIS 安装程序。

## 结构

- `src/main`：Electron 主进程，负责窗口、WCL 请求、本地加密设置、图标缓存和原生导出。
- `src/preload`：通过 `contextBridge` 暴露受限的桌面接口。
- `src/renderer`：React 页面入口、应用编排、通用组件与按功能组织的界面。
- `src/domain`：独立于 UI 与 Electron 的报告解析、区间、事件、选择、MRT／NSRT 格式化和生成数据。
- `src/shared`：主进程、preload 和渲染器共享的接口、校验协议及图标约定。
- `tests/unit/{domain,main,renderer}`：按被测职责分类的单元测试；`tests/electron`：真实桌面集成测试。
- `build`：打包图标；`data`：原始分类观察；`scripts`：开发、数据生成和打包工具。

完整目录树、依赖方向、迁移路径与参考依据见 [项目结构](docs/project-structure.md)。

正式应用从本地 `app://wcl2note` 加载资源，不监听 HTTP 端口。渲染器启用 sandbox、context isolation，关闭 Node integration，禁止直接联网和任意网页导航。
WCL 请求在应用主进程内直接发送；项目中不包含服务端、网页登录、远程认证代理或部署函数。
