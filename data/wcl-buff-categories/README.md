# WCL Buff 分类快照

数据来自 Warcraft Logs 网页实际显示的 Buff 分组，不根据法术名称或效果推断分类。

现有 81 份网页观察采集于 2026 年 10 月 23 日，生成的索引共 1,474 个 ID；紧凑 JSON 为 16,839 字节。

## 采样范围

以下为采集时记录的范围；当前目录不包含排名采样文件，需补齐后才能重新验证排名覆盖率。

- 团本：区域 53，烈毒之渊，排行榜默认的最高难度与指标，每个 Boss、每个职业专精取第一名。
- 大秘境：区域 55，Mythic+ Season 2，使用 `leaderboards=1` 的“仅查看日志”积分榜，每个副本、每个职业专精取第一名。
- 40 个专精，10 个团本 Boss，8 个大秘境，共 720 个采样位置。
- 719 个采样位置有日志，共出现 1,410 个 Buff ID。团本乌拉特克的狂徒专精没有排行榜记录，保留缺项，不以其他名次或难度替代。
- 排行榜是采样时的快照；后续排名变化不会修改已经保存的来源。

## 文件

- `observations.jsonl`：每行一份网页分类观察，保存来源 URL 和 `WCL 分类值 → Buff ID 列表`。只保存该页首次确认的 ID 时标记 `onlyNewSpellIds`；每个保存的 ID 都保留它在该页出现的全部分类。
- `../../src/domain/data/buff-categories.json`：app 使用的紧凑 `spellId → 分类位掩码` 索引，由构建脚本生成。

先通过公开 API 定位榜首日志及对应角色，读取每个角色的 Buff 表并去重。分类取自这些日志的网页 Buff 表。相同 ID 的分类可以复用，因此也读取同一榜首日志中的全队 Buff 表来减少重复工作；所有有日志的采样 ID 都要有网页分类依据。全队表里额外确认的 ID 一并保留。

## 位掩码

同一 Buff 可以属于多个分组，使用按位或保存。显示顺序与 WCL 网页一致：

| 值  | WCL 分组                  | app 名称         |
| --- | ------------------------- | ---------------- |
| 128 | Major Group Cooldown      | 团队大招         |
| 256 | Major Individual Cooldown | 个人大招         |
| 1   | Damage Buffs              | 伤害增益         |
| 4   | Defensive Buffs           | 防御增益         |
| 2   | Healing Buffs             | 治疗增益         |
| 8   | Movement Buffs            | 移动增益         |
| 16  | Raid Buffs                | 团队增益         |
| 64  | Stances, Forms and Seals  | 姿态、形态与圣印 |
| 32  | Toy Buffs                 | 玩具增益         |

例如 `80353: 161` 表示时间扭曲属于 WCL 的团队大招、伤害增益和玩具增益三个分组，`161 = 128 | 1 | 32`。保留网页原始标签，即使部分标签的含义不直观。

`0` 表示网页没有给该 ID 分配上述分类。app 将值为 `0` 和未收录的 ID 都放入“其他”，内部使用独立的 `512` 标记。“其他”不会与已收录的 WCL 分类同时出现。

app 加载索引后按 ID 直接查表，以按位与判断分类。索引不包含来源元数据，app 运行时无需访问排行榜或日志网页。Buff 在多个分组中展示同一行数据，勾选状态同步，MRT 导出不重复计入。

## 更新与检查

新增观察时先核对网页的角色、战斗和完整 Buff 分类表，再保存 ID 及全部分组。施法 ID 不能代替 Buff ID，名称相同的不同 ID 也不能合并。

构建脚本验证来源 URL、分类值和法术 ID；同一 ID 在不同观察中出现冲突会中止生成，防止静默覆盖。采样缺项与真正未分类的 Buff 分开记录。

运行 `npm run build:buff-categories` 从网页观察生成索引，运行 `npm run check:buff-categories` 检查索引是否与观察一致。app 构建会先验证观察并生成索引，不依赖排名采样文件。

若需审计排名采样覆盖率，先在本目录提供以下文件，再运行 `npm run check:buff-coverage`：

- `samples.jsonl`：每行一个采样位置，包含排行榜、第一名角色、日志、战斗、角色 ID 和实际出现的 Buff ID。
- `snapshot.json`：采样时间、区域、Boss / 副本名单和覆盖统计。

覆盖率检查会验证采样完整性、观察的日志来源及所有采样 ID 的网页分类依据；缺少文件或校验不通过时会报错。
