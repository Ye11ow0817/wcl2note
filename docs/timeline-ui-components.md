# 时间轴控件调研（2026-10-26）

当前采用 [Ant Design Slider](https://ant.design/components/slider-cn/)（`antd` 6.6.8）替换全局概览的自绘范围控件。使用 `range.draggableTrack` 支持整段平移，两个手柄控制可见时间区间；时间值以战斗毫秒存储，刻度、拖柄上方的区间时间和无障碍文本格式化为分秒。浮动提示设置 `tooltip.open: false`、`tooltip.formatter: null`，避免拖动时触发其 Portal 循环更新。通过局部 `ConfigProvider` 匹配应用暗色主题，不加载全局重置样式。Phase 仅保留导航按钮和主时间轴的阶段分界线，概览不显示色带。

滑块与阶段导航、框选放大、画布平移、Shift＋滚轮、工具栏和每场战斗的视窗状态双向同步；默认显示前 20 秒，保留两秒最小视窗，短于两秒的阶段仍按真实区间定位。技能时间轴继续使用现有实现，刻度最小大格为一秒，分为两个半秒中格和十个十分之一秒小格。

2026-10-27 起按操作区域区分导航职责：概览滑块负责大范围定位与调整视窗；时间刻度尺固定用于框选放大（至少两秒，Esc 取消），技能行空白及行下方画布固定用于拖动平移。鼠标模式开关和左右平移按钮已移除，工具栏只保留放大、缩小、恢复默认视窗和已选过滤。恢复按钮与画布的 Home 键保持一致：全部阶段恢复默认前 20 秒，具体阶段或 Pull 恢复其完整范围。导航仅改变可见范围，事件详情与 Note 勾选继续由点击和复选框控制。

范围条采用视频裁剪框样式：24px 高的深色轨道、青绿色选区边框和两端 16px 宽的竖向拖柄，选区中部保留整体平移的抓握标记。两个拖柄向选区外侧展开，避免最小两秒视窗下互相遮挡；仍使用原有 Ant Design 滑块节点及键盘、无障碍和范围约束。概览轨道两端预留按文字宽度计算的留白，可见区间时间始终固定在两端拖柄的外侧上方，到达边缘时仍保持相同对齐，不再切换标注位置；下方刻度始终包含完整范围的首尾时间，邻近的中间刻度会避让。轨道刻度不显示圆点。技能行不再绘制每秒的贯穿竖线，保留顶部刻度尺和阶段分界线。「清除全部」统一放在图表与时间轴共用筛选栏的第一行右侧，切换视图不改变按钮位置。有勾选时显示红色图标、文字和边框，无勾选时置灰禁用；状态按整场战斗的实际事件选择判断，忽略仅记录取消勾选的覆盖项，并保留清除其他阶段勾选的能力。界面移除概览标题、刻度尺左侧说明、拖选提示和未选中事件时的底部帮助文字，实际事件详情仅在选中事件后出现。

2026-10-28 起，「全部事件／已加入 Note」改为共用事件类型行右侧的分段切换，图表与时间轴共享显示范围，不再放在缩放工具栏内。阵营提供全部／队友／敌对，默认队友；时间轴仅在「全部」下显示敌对、队友分类及折叠，单阵营直接展示角色与技能。移除技能置顶，保留隐藏与恢复，二者均不改变 Note 勾选。图表保持原有角色排行、技能条形图及统计列布局。

2026-10-29 起，视图、阵营、显示范围和 Note 格式共用「中性浮层」分段控件：深色底槽、灰色选中块、细边框和浅阴影，选中项使用较亮文字及 500 字重。三组工作区控件使用 32px 按钮与 7px 圆角，Note 标题栏使用同一规则的 24px 紧凑尺寸；青绿色用于键盘焦点和事件分类页签下划线。视觉规则集中在 `.segmented-control`，各组只保留尺寸与布局差异。

2026-10-30 起，工作区按确认方案收为三行：第一行将 Actor 放在 22px 高的阵营按钮上方，右侧图表／时间轴按钮为 56px 高；第二行为事件类型与显示范围；第三行为 Target／Source，右侧集中放置配置选择、保存和清除勾选。「另存为、配置管理」收入原有配置下拉，战斗与阶段导航仍然独立。共用筛选栏与内容面板连接，减少重复边框和区块间距。

时间轴缩放按钮与范围条并排放在约 72px 高的导航区；范围时间继续固定在拖柄外侧上方，主时间轴的时间文字改在刻度线上方。所有阵营都允许按单位折叠，折叠状态沿用每场战斗的视图记忆，切换阵营和图表／时间轴时继续保留；仅「全部」显示阵营分类标题，其分类折叠不会隐藏单阵营内容。单位折叠不改变 Note 勾选，技能详情继续使用原有完整、可收起的表格面板。

时间轴排序单独对齐 WCL：阵营内的单位按当前阶段及来源／目标筛选后的事件合计次数降序，单位内的技能按次数降序；同次数直接比较名称，采用 WCL 的字符顺序，不使用中文拼音排序。同名单位再按角色 ID、实例编号固定顺序，避免技能行交错。全部阵营仍保持敌对在前，缩放、隐藏与 Note 勾选不参与排序。Buff／Debuff 的获得、刷新与叠层均计入排序次数，刷新与叠层只保存统计时间，不新增可导出的获得事件；跨阶段延续的效果只统计当前阶段内的次数。现有按单位分组结构保留，WCL Buff 页的多分类重复分组仍仅用于图表布局。

## 通用时间轴候选

结合秒级战斗时间、固定技能行、图标自然重叠和 Note 逐次勾选需求，`vis-timeline` 是整体替换时更接近的候选。以下结论来自官方能力对比，尚未在本项目完成集成和性能验证。

| 控件                                                                               | 已核对的官方能力                                                                                                | 本项目仍需适配                                                                                             |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| [vis-timeline](https://visjs.github.io/vis-timeline/docs/timeline/)                | 拖动和缩放、毫秒级刻度、分组、HTML 模板、自定义刻度格式；设置 `stack: false`、`cluster: false` 可让事件自然重叠 | 战斗相对时间格式、技能图标和读条、阶段导航、选中与导出状态、React 生命周期管理                             |
| [react-calendar-timeline](https://github.com/namespace-ee/react-calendar-timeline) | 受控可见时间范围、`itemRenderer`、`groupRenderer`，以及 `stackItems: false`                                     | 默认按日历时间工作，需调整 `minZoom` 和刻度；还需验证本项目 React 19、秒级窗口、图标边缘裁切和密集事件表现 |

两者都是通用时间轴，提供缩放手势和范围控制能力，默认不带完整的缩放工具栏或全局概览滑块。默认皮肤不会直接成为 WCL 技能时间轴。替换底层时仍应保留现有事件身份、Note 选择和来源／目标筛选逻辑，并禁用修改事件时间或所属技能行的编辑操作。

若后续整体替换，建议先用 vis-timeline 验证 20 秒和全战斗窗口、同毫秒事件、跨视窗读条、两端图标裁切、嵌套角色分组及键盘操作，再确定迁移范围。

官方参考：[vis-timeline 配置与模板](https://visjs.github.io/vis-timeline/docs/timeline/)、[vis-timeline 示例](https://visjs.github.io/vis-timeline/examples/timeline/)、[react-calendar-timeline 文档](https://github.com/namespace-ee/react-calendar-timeline)。
